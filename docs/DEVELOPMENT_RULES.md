# 开发规范

版本：V1.0

## 基本要求
- 先定义接口和验收，再实现代码。
- MVP 优先模块化单体，避免过早微服务化。
- 模型、存储、向量库、浏览器和媒体处理器通过适配层接入。
- 关键行为可测试、可观测、可回滚。
- 不提交密钥、令牌、个人数据、真实客户数据或大型模型权重。

## 建议目录
- docs：产品、架构、技术、路线图、验收、安全和规范。
- src/core：领域模型与公共接口。
- src/model_gateway：模型路由与适配。
- src/ingestion：资料接入。
- src/media：视频、音频、OCR 与抽帧。
- src/knowledge：知识与证据。
- src/skill_compiler：技能生成与检查。
- src/evaluation：测试、评分和回归。
- src/memory：专家记忆。
- src/execution：沙箱与工具执行。
- src/orchestration：专家与任务调度。
- tests、experiments、scripts、configs、ADR：测试、实验、脚本、配置和决策记录。

目录可随验证调整，不为匹配文档而提前创建空模块。

## 代码质量
使用类型标注和明确数据契约；输入输出做 schema 校验；错误使用稳定错误码；外部调用设置超时、重试上限和幂等策略；日志带 trace_id、task_id、expert_id；密钥通过环境变量或受控配置注入；关键逻辑有单元与集成测试。

## Git 工作流
main 保持可运行；功能使用独立分支和 PR；PR 描述背景、实现范围、测试证据、风险和回滚；不强推 main，不重写共享分支历史。提交信息使用清晰范围和动词，例如 docs: add architecture。

## AI 编码代理约束
先读取文档、现有代码和测试，不得臆造仓库结构；大改动先拆任务；不得擅自更换 Qwen 3.5 4B/9B 主模型方向或扩大范围；不得把候选依赖写成已验证依赖；不得删除测试、降低门槛或伪造结果；未经授权不得发布、支付、删除或授权外部账号。完成后报告改动文件、测试命令、真实结果、未解决问题和建议。

## 决策记录
重大技术选择写 ADR：背景、候选、决策、理由、代价、验证证据和重新评估条件。未经测试的判断标记为假设。
