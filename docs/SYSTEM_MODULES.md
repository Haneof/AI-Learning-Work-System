# 完整模块系统与端到端工作闭环

版本：V1.0  
状态：目标架构 / 研发基线（不是已全部实现的功能清单）

## 1. 产品目标

AI Learning & Work System 要培养能够持续学习、独立承担专业任务、验证交付结果并从工作经验中改进的专业 AI。

系统不是单一聊天机器人，也不只是教程总结器。它由三个相互连接的闭环构成：

- **学习闭环**：发现资料 → 获取资料 → 质量筛选 → 多模态理解 → 知识组织 → 技能形成 → 训练与考核 → 发布可用技能。
- **工作闭环**：接收任务 → 理解与规划 → 技能选择 → 工具执行 → 观察与状态管理 → 结果验证 → 交付 → 经验复盘。
- **进化闭环**：工作中识别能力缺口 → 创建学习任务 → 补充资料和训练 → 重新考核 → 版本化发布技能。

学习系统负责培养能力；工作系统负责使用能力；工作产生的经验经过验证后反馈学习系统。

## 3. 顶层子系统与模块清单

### A. 教程发现与资料采集系统（Acquisition）

目标：持续发现公开可访问的教程和专业资料，并可靠地进入本地资料资产库。

1. **领域与任务目录**：管理专业领域、软件/工具、岗位、任务类型和搜索主题；扩展关键词、同义词、多语言关键词和关联主题。
2. **来源连接器**：对接视频平台、搜索引擎、开源社区、官方教程站、技术博客和文档站；每种来源使用独立适配器，统一输出候选资源结构。
3. **链接发现引擎**：关键词搜索、站内搜索、网页链接抽取、仓库 README/文档链接抽取；支持定期重搜、增量发现、分页、速率限制和失败重试。
4. **候选资源登记**：保存 URL、标题、作者/频道、来源站点、时长、发布时间、语言、分辨率等可获得元数据；URL 规范化、候选去重、来源追踪和发现批次记录。
5. **解析下载引擎（复用成熟工具，不自研下载内核）**：
   - 视频页面/平台媒体解析优先集成 yt-dlp；复用其站点 extractor、HLS/DASH 处理、分片并发和媒体合并能力。
   - 普通 HTTP 大文件优先调用 aria2；服务端支持 Range 时使用多连接分段和断点续传，否则退化为顺序下载。
   - FFmpeg/ffprobe 负责媒体探测、音视频合并、音轨抽取和可解码性检查。
   - 本系统只开发统一 Job API、引擎适配器和调度层：参数转换、任务生命周期、进度/错误解析、重试、暂停恢复和输出校验；不重写媒体协议。
   - 下载后检查文件大小、SHA-256、媒体流、时长和可解码性，再登记 MediaAsset。
   - 不实现 DRM 破解、访问控制绕过或未授权凭据获取。
6. **媒体资产登记**：原始文件只读保存；生成 asset_id、内容哈希、文件格式、大小、来源和下载记录；原始文件、派生文件、处理版本分开存储。
7. **采集调度与队列**：管理发现队列、下载队列、失败重试、并发配额、优先级和暂停恢复；支持多个采集节点共享任务状态，避免重复下载。

### B. 视频与资料筛选系统（Curation）

目标：判断资料是否可用，并区分不同类型的学习价值，不简单地只保留长教程。

1. **基础质量筛选**：文件完整性、解码能力、时长、清晰度、音轨、字幕和损坏检测。
2. **重复与近重复识别**：URL/哈希精确去重；对转码、裁剪、重复上传版本使用感知哈希或内容指纹辅助识别。
3. **内容相关性筛选**：判断是否与目标专业、工具、任务和技能有关。
4. **教程类型分类**：完整教程、单项技巧、问题排查、案例演示、理论讲解、产品宣传、无关内容等；短视频和专项教程可进入专项资料库，不因不完整而一律删除。
5. **教学质量评分**：操作可见性、步骤完整度、讲解清晰度、信息密度、实操价值和版本适用性。
6. **人工复核队列**：对低置信度、冲突内容和高价值样本进行人工抽查。
7. **筛选结果管理**：通过、待复核、拒绝、专项保留等状态；保留判定原因，支持规则迭代。

### C. 多模态理解与数据提取系统（Understanding）

目标：把原始视频和资料转换为带时间位置、可追溯的结构化证据。

1. 媒体预处理：探测媒体信息、抽取音轨、标准化采样、镜头/场景切分。
2. 字幕与语音：提取原字幕；无字幕时 ASR；保留语言、时间戳和置信度。
3. 关键帧提取：按场景变化、画面变化、操作事件和时间间隔抽帧。
4. OCR 与界面理解：识别菜单、按钮、文本框、窗口、提示和页面状态。
5. 动作识别：识别点击、输入、选择、拖拽、快捷键、滚动、文件操作等可观察动作。
6. 时间轴对齐：将语音、字幕、画面、OCR 和动作候选对齐到统一时间线。
7. 步骤候选抽取：生成目标、前置条件、动作、目标对象、预期状态、证据引用和恢复策略。
8. 证据质量管理：明确区分字幕证据、视觉证据、OCR 证据和人工确认；不能用旁白代替画面证明实际操作。
9. 跨资料对照：识别不同教程的共同步骤、不同方法、版本差异和相互矛盾之处。

### D. 知识组织与专业知识库（Knowledge）

目标：从分散资料中形成有来源、可检索、可更新的专业知识。

1. **多层分类体系**：专业领域 → 专业方向/工具 → 任务类型 → 技能 → 操作知识点。
2. **知识抽取**：概念、事实、规则、约束、流程、条件、例外、风险、故障原因和解决办法。
3. **实体与关系**：工具、版本、文件类型、操作、参数、任务、前置条件和结果之间的关系。
4. **证据绑定**：每条知识保留 source_id、asset_id、页码/时间戳、帧引用、提取方式和审核状态。
5. **去重与冲突处理**：合并重复知识，但保留不同来源；冲突按软件版本、环境、前置条件和证据强度分别记录，不强行抹平。
6. **知识版本与生命周期**：候选、审核、有效、过期、被替代；支持知识更新和回滚。
7. **专业隔离**：知识按 expert_id/专业空间隔离，跨专业共享必须经过明确授权接口。

### E. 技能编译、训练与能力评估系统（Learning & Skill）

目标：把知识和示范流程转化为可调用、可测试、可版本化的技能。

1. **技能候选生成**：从多个来源归纳目标、适用条件、输入输出、步骤、分支和异常处理。
2. **技能包编译**：形成技能说明、机器可读契约、工具依赖、权限需求、测试用例和证据来源。
3. **静态检查**：检查字段、依赖、权限、危险操作、输入输出和版本兼容性。
4. **训练环境**：使用确定性模拟器、测试数据、沙箱和可控应用环境练习。
5. **技能评测**：步骤正确率、任务完成率、恢复能力、结果质量、效率和安全约束。
6. **迁移评测**：在未见数据、界面变化、参数变化和异常条件下验证技能是否稳健。
7. **晋级门禁**：未达到岗位定义的标准，不得发布为正式技能；候选技能与已认证技能分开。
8. **技能注册与版本管理**：技能有唯一 ID、版本、状态、兼容范围、评测报告和变更记录；可回滚。
9. **能力缺口学习**：工作执行发现技能缺失、过期或评测不通过时，创建补学/重训任务。

### F. 专业 AI 工作系统（Work Runtime）

目标：让已经获得认证技能的专业 AI 能接任务、计划、执行、检查并交付真实工作成果。

1. **任务入口（Task Intake）**：接收用户指令、其他 Agent 委派、外部 API/事件和定时任务；将请求转成结构化任务，包括目标、输入、输出、约束、期限、优先级、验收标准和权限范围。
2. **任务理解与规划（Planner）**：判断任务类型、拆解子任务、估算资源、识别依赖和风险；选择技能、工具和模型；执行中根据观察结果动态重规划。
3. **技能检索与调用（Skill Runtime）**：检索已认证技能；检查版本、适用条件、输入契约、依赖和权限；组合多个技能并记录输入输出。
4. **工具接入与路由（Tool Gateway）**：统一连接浏览器、桌面 GUI、命令行、Python、文件、数据库、API 和业务应用；工具适配器声明 schema、权限、超时、幂等策略和结果结构。
5. **执行引擎（Execution Engine）**：驱动 observe → decide → act → observe 循环；管理步骤状态、并发、超时、重试、检查点和中断恢复；支持长任务、子任务、依赖关系和补偿操作。
6. **上下文与任务记忆（Context Manager）**：管理当前任务上下文、文件引用、工具结果、历史步骤和摘要；区分临时任务状态与长期专业记忆。
7. **异常诊断与恢复（Recovery Manager）**：识别工具错误、页面变化、数据异常、模型错误和前置条件不满足；调用已验证恢复技能；限定重试次数和恢复预算；无法安全恢复时暂停并请求人工介入。
8. **结果验证（Verification Engine）**：每类任务定义独立验收器，例如文件结构/内容检查、代码测试、数据校验、页面状态检查和业务规则检查；验证实际结果，不以模型自述作为完成依据。
9. **交付模块（Delivery）**：输出文件、报告、数据、操作结果和证据摘要；检查交付物可访问、格式正确、内容完整，并记录交付状态。
10. **人工接管与审批（Human-in-the-loop）**：对高风险、不可逆、权限不足或低置信度动作请求批准；支持暂停、接管、修改计划、恢复执行和最终确认。

### G. 工作经验与持续进化系统（Experience & Evolution）

目标：让每次工作产生可复用经验，但防止未经验证的错误经验污染技能库。

1. **任务轨迹**：保存计划、步骤、工具调用、观察结果、错误、重试和交付物引用。
2. **成功经验**：记录有效策略、适用条件、输入特征和验证结果。
3. **失败经验**：记录失败现象、根因假设、已尝试方案和最终解决方式。
4. **经验提炼**：从多个任务轨迹归纳候选规则、提示、流程改进和新技能候选。
5. **经验验证**：通过复现、回归测试和未见任务验证后，才允许进入正式知识或技能版本。
6. **能力缺口分析**：统计任务失败、人工接管、技能缺失、技能过期和低质量结果，生成学习任务。
7. **持续回归**：新技能发布前运行已有任务集，避免更新导致旧能力退化。

### H. 多专业 AI 协作系统（Multi-Agent Collaboration）

目标：让不同专业 AI 通过任务协议协作，而不是互相进行无结构聊天。

1. **专家注册中心**：登记专业范围、能力声明、技能目录、版本、状态和可用资源。
2. **委派与路由**：按任务类型、能力、负载和权限选择专家。
3. **任务协议**：传递目标、输入、约束、输出 schema、验收标准、截止时间和状态。
4. **协作编排**：支持顺序、并行、依赖、评审和汇总。
5. **结果与冲突处理**：比较专家结果、证据和置信度；冲突交由规则或人工解决。
6. **隔离边界**：专家不直接读取其他专家的私有知识、技能、长期记忆和工作经验；只能通过授权接口获得必要信息。
7. **共享通用底座**：模型、视觉能力、工具网关、调度和基础设施可共享。

### I. 共享平台与治理底座（Core Platform）

1. **Model Gateway**：模型注册、路由、版本、能力声明、上下文策略、超时和成本记录。
2. **Memory Service**：任务记忆、专业知识、技能索引和工作经验分区管理。
3. **Data & Asset Service**：文件/对象存储、元数据、关系数据、向量索引和版本管理。
4. **Task Orchestrator**：任务队列、调度、优先级、依赖、重试、定时触发和分布式节点。
5. **Tool Gateway**：统一工具 schema、连接器、凭据引用、权限和审计。
6. **Identity & Access Control**：用户、Agent、专家、角色、资源和操作权限。
7. **Sandbox & Isolation**：脚本、插件和技能执行隔离；资源配额和网络策略。
8. **Audit & Observability**：结构化日志、trace、指标、告警、成本、资源占用和操作审计。
9. **Evaluation Platform**：数据集、基准任务、评分器、回归测试、门禁和报告。
10. **Admin Console**：专业 AI、采集任务、工作任务、技能版本、资源和运行状态管理。

## 3.1 教程发现接口基线

平台搜索采用统一的 SearchRequest / SearchPage / ResourceCandidate 契约；每个平台通过 SourceSearchAdapter 独立接入，由 AdapterRegistry 显式注册。搜索仅返回候选元数据，不自动下载。候选按平台与规范化 URL 去重，平台特有的资源定位参数必须保留。

已落地 SearchService、PlatformCatalog、BilibiliSearchAdapter 和 SQLite CandidateRepository。Bilibili 适配器实现 WBI 签名的视频关键词搜索和分页字段映射；当前单元测试使用注入的假 transport，尚未证明真实网络环境可用。候选仓储支持跨搜索批次去重关联及人工筛选状态迁移。

详细接口、平台能力矩阵和验收标准见 [ACQUISITION_DISCOVERY_DESIGN.md](ACQUISITION_DISCOVERY_DESIGN.md)。

## 4. 核心对象与数据边界

系统至少区分以下对象，不把它们混成一张“知识表”：

- **Source**：网页、频道、仓库、文档站等来源。
- **ResourceCandidate**：发现的候选链接和元数据。
- **MediaAsset**：下载后的原始视频/音频/文档文件。
- **DerivedAsset**：字幕、音轨、关键帧、OCR、切片等派生资产。
- **Evidence**：可定位的原始证据，如视频时间戳、帧、文档页码。
- **KnowledgeItem**：事实、概念、规则、条件、流程和异常知识。
- **SkillPackage**：带契约、步骤、工具、权限、测试和证据的技能版本。
- **EvaluationRun**：训练、测试、基准和回归评测记录。
- **ExpertProfile**：专业 AI 的身份、职责、能力和隔离空间。
- **Task / Episode**：工作任务、子任务、执行轨迹和状态。
- **ToolCall**：工具请求、权限判定、输入输出和结果。
- **Artifact**：任务产生的文件、报告、数据和交付物。
- **ExperienceRecord**：经过验证或待验证的成功/失败经验。
- **AuditEvent**：重要状态变化、权限决定和人工审批。

所有对象通过稳定 ID 关联。原始资料不可被抽取结果覆盖；知识与技能保留来源；工作任务引用实际使用的技能版本。

## 5. 关键端到端流程

### 5.1 从公开教程到正式技能

领域/任务定义 → 搜索关键词生成 → 多来源发现 → 候选链接去重 → 视频解析与下载 → 文件校验 → 质量筛选 → ASR/OCR/关键帧/动作提取 → 时间轴对齐 → 步骤候选 → 多教程比较 → 知识分类 → 技能编译 → 静态检查 → 沙箱训练 → 未见任务评测 → 验收 → 发布技能版本。

### 5.2 从用户任务到工作交付

接收任务 → 结构化任务单 → 风险与权限检查 → 任务拆解 → 专家/技能/工具选择 → 执行计划 → 工具操作 → 观察状态 → 结果验证 → 必要时修复/恢复/重规划 → 交付物检查 → 用户交付 → 任务轨迹归档。

### 5.3 从工作失败到能力进化

执行失败/人工接管/质量下降 → 诊断根因 → 判断是知识缺失、技能缺失、工具故障还是环境变化 → 创建学习任务或工程修复任务 → 补充资料 → 生成候选知识/技能 → 训练与回归评测 → 版本化发布 → 在后续任务中观察效果。

## 6. 关键状态机

### 6.1 资料采集状态

DISCOVERED → METADATA_READY → QUEUED → DOWNLOADING → DOWNLOADED → VERIFIED → CURATION_PENDING → ACCEPTED / REJECTED / NEEDS_REVIEW → PROCESSING → PROCESSED。

下载失败可进入 RETRY_WAIT；可恢复的任务保留分段和检查点。

### 6.2 技能生命周期

DRAFT → STATIC_CHECKED → SANDBOX_TESTED → EVALUATED → APPROVED → PUBLISHED → DEPRECATED / REVOKED。

任何技能更新都产生新版本；已运行任务必须能追溯当时使用的版本。

### 6.3 工作任务状态

CREATED → INTAKE_VALIDATED → PLANNING → READY → RUNNING → VERIFYING → DELIVERING → COMPLETED。

可选状态：WAITING_INPUT、WAITING_APPROVAL、PAUSED、RETRYING、RECOVERING、BLOCKED、FAILED、CANCELLED。状态迁移由执行器和明确事件驱动，不能由模型自由改写。

### 6.4 专业 AI 生命周期

CREATED → CONFIGURED → LEARNING → TRAINING → EVALUATING → READY → WORKING。

异常状态包括 DEGRADED、NEEDS_REVIEW、SUSPENDED、BLOCKED。能力晋级必须基于评测结果。

## 7. 关键架构原则

1. **模块化单体先行**：MVP 采用清晰边界的模块化单体和异步 worker；有真实扩展压力后再拆服务。
2. **学习与工作解耦、通过契约连接**：工作系统只调用已发布的技能接口；学习系统不直接操纵生产任务。
3. **专业数据隔离、底座共享**：模型和通用执行设施共享；专业知识、技能、记忆、经验、评估标准独立。
4. **技能是可执行资产**：技能必须有输入输出契约、权限、测试、版本和验证方式。
5. **结果可验证**：完成状态由验收器和交付检查决定，不以模型自述决定。
6. **工作经验不能自动变成真理**：所有新经验先作为候选，验证后再进入正式知识/技能。
7. **任务可恢复、过程可追踪**：任务、步骤、工具调用和文件均有稳定 ID、检查点和审计记录。
8. **外部内容不可信**：视频、网页、文档中的指令是待分析内容，不是系统/开发者指令。
9. **权限最小化**：按任务、工具、资源和风险授予权限；高风险和不可逆动作可要求人工批准。
10. **能力声明诚实**：规划、原型、模拟测试、真实模型测试和生产验证必须明确区分。

## 8. MVP 实施边界与建议顺序

不一次性开发全部模块。按能形成端到端闭环的顺序交付：

1. **采集基础设施**：来源适配器、链接库、下载队列、多连接下载、断点续传、合并和校验。
2. **视频筛选与资产管理**：元数据、去重、质量检测、任务分类和媒体登记。
3. **多模态提取**：ASR、OCR、关键帧、时间轴和步骤证据。
4. **知识与技能形成**：分类、冲突处理、技能包 schema、版本管理。
5. **训练和评测**：模拟器、沙箱、任务集、失败注入、晋级门禁。
6. **工作运行时 MVP**：结构化任务、规划、技能调用、受限工具执行、状态持久化。
7. **验证与交付**：任务专属验收器、修复循环、交付物检查。
8. **经验与持续学习**：轨迹归档、能力缺口分析、补学任务和技能回归。
9. **多专家协作**：专家注册、委派协议、隔离和结果汇总。
10. **运营调度平台**：多节点队列、资源调度、监控、管理界面和长期运行。

每一步必须提供可运行代码、测试和验收证据。文档中的目标模块不代表已实现；具体实现状态以代码、CI 和真实环境测试为准。

## 9. MVP 首个端到端验收

选择一个低风险、可客观验证的专业任务，贯通以下链路：

1. 系统发现至少一组教程链接并登记候选资源。
2. 下载器完成可续传下载、分段合并和文件校验。
3. 筛选器将资料分类并保留拒绝原因。
4. 解析器生成带时间戳的字幕、关键帧和步骤证据。
5. 知识服务生成可追溯的任务知识。
6. 技能编译器生成候选技能并通过静态检查。
7. Agent 在模拟器或隔离环境中调用该技能完成未见测试任务。
8. 验收器独立检查结果；失败时触发受限恢复。
9. 任务结果和经验记录归档；只有通过门禁的技能才发布。
10. 后续工作任务能够按技能 ID/版本检索并调用该技能。

首个闭环通过后再扩展更多专业领域和真实应用工具。
