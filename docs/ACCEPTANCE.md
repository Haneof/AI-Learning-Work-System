# 验收标准

版本：V1.0。具体数值阈值由试点基线测试确定并版本化。

## 端到端闭环
1. 导入真实专业资料并生成唯一 source_id。
2. 完成解析，保留页码、时间戳或片段定位。
3. 提取知识条目并回溯原始证据。
4. 编译技能草案并通过结构和依赖检查。
5. 在隔离沙箱执行技能测试。
6. 输出结构化测试报告。
7. 诊断失败并生成新技能版本。
8. 使用未见任务验证，而非只重复原样例。
9. 记录成功/失败经验并在后续任务中正确检索应用。

## 知识验收
- 关键结论带来源定位。
- 区分原文事实、模型推断和建议。
- 不确定内容明确标记，不伪造证据。
- 多来源冲突保留双方证据、时间和版本。
- 过期信息可标记并阻止无条件使用。
- 抽样人工核验准确性与遗漏。

## 技能验收
- 具备目标、范围、前置条件、输入输出。
- 关键步骤有成功判据。
- 包含条件分支、异常处理和终止条件。
- 明确工具、权限和外部副作用。
- 有正向、负向、边界和异常测试。
- 版本变更触发回归测试。
- 不以模型自评作为唯一通过依据。

## 执行验收
- 执行前进行权限判定，参数经过 schema 校验。
- 关键步骤保留证据，结果由独立检查器或可观察状态验证。
- 超时、失败和部分成功有明确状态。
- 高风险操作暂停等待人工批准。
- 不把点击成功误报为业务结果成功。

## 学习进化验收
- 从失败轨迹提取明确能力缺口。
- 学习任务关联原始失败任务。
- 新技能隔离验证后才发布。
- 失败不污染正式技能库。
- 新版本运行回归集并可撤销回滚。

## 专家隔离验收
- 专家 A 默认不能检索专家 B 的私有记忆。
- 跨专家调用显式授权。
- 任务、技能、日志和评估结果带 expert_id。
- 专家停用时按策略处理数据。
- 专家不能自行提升资源配额或权限。

## 发布阻断
关键知识无证据、技能高危步骤未处理、回归失败、权限可绕过、结果验证缺失、审计缺失或依赖许可未确认，均阻止发布。
